# Contributing

Bug reports, compatibility results and pull requests are welcome. For setup help,
start with the [README](README.md#setup). Use the issue templates to report a bug,
request a feature or share results from another model.

Include the project version, HA version, broker and setup computer OS when they're
relevant. Remove tokens, passwords, private keys, full MAC addresses and personal
network details from logs. Don't upload an installation bundle.

For code changes, follow the [development instructions](README.md#development).
Keep code and tests under `src/`, and edit shared modules in `src/winix_local/`.
The HA `_core/` package is generated by the ZIP build.

Add tests for behavior changes and run `make validate` before opening a pull
request. Explain what you tested. If you've tested hardware, name the exact model
and controls you used. Adding catalog metadata alone doesn't establish support.

Please keep unrelated formatting changes out of a fix. Contributions use the
project's [MIT license](LICENSE).

## Releases

Maintainers update `pyproject.toml`, `manifest.json` and `CHANGELOG.md` together.
After the change is committed and pushed, push an annotated tag matching the
version, for example `v0.1.0` for version `0.1.0`.

The Release workflow compares setup-tool source, dependencies, launchers and build
inputs with the latest published release. Tool changes run the full platform,
executable and installation checks. HA-only releases run Linux and HA checks,
rebuild the HACS ZIP and Python distributions, and reuse the existing setup
executables after verifying their published checksums.

Every release gets launchers pointing at its own tag and fresh checksums. A tag
push publishes a release after these checks pass. It doesn't deploy HA or publish
to PyPI. The repository and releases are public. HACS users add it as a custom
repository.

The **Install release** workflow can also check an already-published version.
Run it manually from Actions and supply its tag. It installs the downloaded wheel
in a fresh environment outside the checkout with `--only-binary=:all:`. If a
required dependency has no wheel for that platform, the check fails instead of
compiling it.
